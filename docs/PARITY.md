# Sapphire Windows parity matrix

This detailed upstream comparison began before the V1 release and retains historical acceptance notes. For current download behavior (including hidden tray startup), use [INSTALL.md](INSTALL.md); current feature boundaries and package results are in [FEATURES.md](FEATURES.md) and [VERIFICATION.md](VERIFICATION.md).

Reference source is pinned to [`792f9b4ea3d556d7566fbc38592fe54e88d89dc0`](https://github.com/cshariq/Sapphire/tree/792f9b4ea3d556d7566fbc38592fe54e88d89dc0). The [upstream README](https://github.com/cshariq/Sapphire/blob/792f9b4ea3d556d7566fbc38592fe54e88d89dc0/README.md) and [product website](https://sapphire-app.tech/) were inspected on 2026-10-25. Website content is an observed product specification, not a versioned implementation or evidence of Windows behavior. Reference videos have not been played through or measured frame by frame; native macOS behavior has not been executed here.

The Windows target is a desktop adaptation: a top notch, taskbar launcher, notification-area controls, real local data and supported Windows APIs. This matrix accounts for the advertised feature areas. It does not claim literal A–Z macOS parity.

Geometry and motion references at that revision:

## Status rules

- **Source implemented; runtime pending**: the route and its command/data path exist. Compilation, automated checks and desktop smoke results are listed separately in [VERIFICATION.md](VERIFICATION.md). This status does not accept hardware, provider or installed-app behavior.
- **Partial**: a useful subset exists, with missing behavior stated in the row.
- **Unavailable**: deliberately excluded by the standard Windows API boundary or an unavailable upstream implementation.
- A feature is accepted only after its observable check passes on the intended Windows installation. Missing configuration must produce a visible requirement/error, never sample data or fabricated success.

## Public source versus hosted product

The pinned public tree contains executable macOS UI/utility code and build-conditioned placeholders. In particular, [`Sapphire/Stubs/IntelligenceNotchView.swift`](https://github.com/cshariq/Sapphire/blob/792f9b4ea3d556d7566fbc38592fe54e88d89dc0/Sapphire/Stubs/IntelligenceNotchView.swift) renders an unavailable notice outside the full build. That stub cannot supply Blip's private agent implementation. The website's proprietary authentication, subscription and hosted agent behavior must not be represented as recovered public code.

This port implements its own bounded Gemini integration, Windows Hello action verification, and provider integrations. It neither bypasses subscriptions nor copies a hidden service. No provider account was purchased, no paid plan was activated, and no user API key is required to build. A saved key indicates local configuration, not validated provider connectivity.

## Remaining acceptance gates

Reference video playback, measured visual comparison, native macOS execution, clean-VM installation, package signing/identity validation, mixed-DPI monitors, user-app media/audio/snapping, physical drag, physical hardware changes, camera consent, Hello outcomes and configured provider calls remain explicit gates. Real read-only native queries and controlled owned-window/silent-audio fixtures have passed as recorded in [VERIFICATION.md](VERIFICATION.md). These results do not establish full feature acceptance.
